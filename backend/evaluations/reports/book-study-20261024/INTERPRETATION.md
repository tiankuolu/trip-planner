# 实验成绩解读

## 同一道题能否重复做好

完整100条任务中，两次都通过的题目数量为：A配置28道、B配置50道、C配置60道。C另有24道题缺少判断“两次全部通过”所需的证据。这些未知任务需要补充价格、开放记录等证据，不能直接计为已经失败。

这个指标能发现重复运行中的不稳定表现。已有固定低温、相同种子的两次执行属于本次经验记录，不能证明未来独立运行的成功概率。

## 重新规划实际解决了多少问题

C的200条记录中，197条可以核验相同调用前缀，三条录制不完整。在相同197条记录中，保留重新规划时通过124次，关闭重新规划时通过111次。重新规划将13次确定失败修复为通过，没有出现“关闭后通过、保留时确定失败”的记录。

关闭重新规划省略45次模型调用。这个数字说明重新规划具有资源开销；离线重放无法提供这些新配置的真实线上耗时，也不能据此推算未来任务效果。保留现有重新规划组件具有本次轨迹证据支持。

## 执行清单是否改善结果

使用20条开发诊断任务，两个配置各运行三次，共120次真实模型执行。每个任务与种子配对，工具数据、评分规则、模型参数和恢复预算相同。W统一每日数量规则并加入执行流程与条件清单。

| 指标 | C：现有配置 | W：执行清单 |
| --- | --- | --- |
| 总体通过 | 42/60，70% | 45/60，75% |
| 每日数量任务通过 | 26/30 | 29/30 |
| 故障任务通过 | 16/30 | 16/30 |
| 三次全部通过的任务 | 11/20 | 14/20 |
| 平均Agent执行耗时 | 15.58秒 | 14.75秒 |
| 平均工具调用 | 3.43次 | 3.48次 |
| Token完整的执行数 | 55/60 | 58/60 |
| 全部执行总Token、费用 | unknown | unknown |

W总体增加三次通过，差值五个百分点。按任务配对抽样的95%区间为负3.3到正15.0个百分点，包含零；三次全部通过的McNemar检验p=0.375。因此，本次数据不足以确认W稳定优于C。每日数量成绩呈改善迹象，故障成绩没有提高。20条任务已经参与开发，不能据此断言对未见任务的效果。

故障任务进一步分组：两组临时故障都是16/18通过，连续故障都是0/12通过。增加清单文字没有解决持续缺少工具数据的问题。现有恢复预算仍会耗尽；后续恢复能力研究需要检查故障后的具体动作、可用证据和完整任务结果。

## 一条可核验的错误轨迹

记录 `daily_count-10-W-1`要求每天恰好两个不同景点。第一次输出未通过数量校验，Agent收到具体反馈后重新规划，最终仍为第一天三个景点、第二天两个景点，最终确定失败。原始模型输出与候选行程保存了同样数量，因此能够定位到模型规划结果违反条件。清单提示与重新规划反馈同时存在，仍需保留最终程序校验。

## 记录与核验

120次在线执行中，113次具有完整响应并离线重放一致，七次包含未收到HTTP响应的调用，无法核验完整调用序列。其中部分执行随后继续完成，任务最终成绩与录制完整性分别报告。没有发现完整录制的重放差异。

Token只有在全部调用证据完整时才汇总。C有五次、W有两次执行缺少完整Token证据，所以两组全部执行的总Token保持unknown。没有提供核实单价，费用同样保持unknown。

127项测试通过，Ruff检查通过。数学评分测试使用明确的逻辑状态输入；本次模型对照使用真实服务与冻结高德数据。生产Agent默认配置保持C/W实验之前的状态，新增提示方式通过实验配置选择。
